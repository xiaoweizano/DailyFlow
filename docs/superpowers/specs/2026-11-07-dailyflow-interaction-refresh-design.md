# DailyFlow 交互刷新与可靠性修复设计

**日期：** 2026-11-07

**状态：** 已确认，可进入实施计划

**范围：** 全局语言、设置与窗口关闭、日志编辑器、时间线、热力图、知识库、待办、帮助中心和关键交互反馈

## 1. 背景

DailyFlow 已具备日志、待办、时间线、知识库、搜索、分析、设置和桌面端能力，但第二轮真实使用验收暴露出一组相互关联的问题：

- 语言切换只刷新设置页，其他页面仍使用旧语言。
- 设置页存在无意义的横线、滚动选择器和难以直接比较的外观控件。
- 日志编辑器功能很多，但入口分散，模板、正文、大纲和保存操作没有形成清晰流程。
- 日志块左侧的六点手柄不可理解，用户无法从中发现可插入的内容。
- 时间线只能用相邻月份或固定年份下拉框导航，难以快速查看历史。
- 热力图活动色不是用户期望的绿色。
- 知识库新建和整篇日志沉淀失败，但界面只显示统一的“请重试”。
- 待办创建失败时没有展示真实校验或后端错误，完成与重新打开操作不够明显。
- 关闭窗口的行为不符合当前测试阶段预期，且无法选择询问、最小化或直接退出。
- 帮助中心缺少清晰入口、格式、操作步骤和截图证据。

## 2. 目标与用户可见结果

1. 在设置中切换语言后，当前窗口立即刷新全部业务页面、日期格式、空状态、错误提示和内置帮助内容，无需重启。
2. 设置页的常规、外观和显示项没有异常横线；主题、强调色和密度直接以可见选项呈现，不使用带滚动条或上下箭头的原生选择器。
3. 新日志从模板选择开始；最近使用、内置模板、自定义模板和空白日志均可直接进入正文。
4. 日志正文使用可发现的当前行 `+` 插入入口；六点块手柄移除，正文、工具栏、大纲和保存状态在常用窗口尺寸内不互相遮挡。
5. Markdown 语法输入继续生效，例如输入 `## 你好` 后生成二级标题并出现在大纲中。
6. 时间线的年、月可以快速跳转，支持任意有效年份，不需要连续点击上月。
7. 月历与热力图统一使用绿色活动色阶。
8. 知识库新建与整篇日志沉淀成功；失败时显示真实可恢复原因，不再用单一通用错误覆盖根因。
9. 待办可以成功创建；每行始终显示完成或重新打开操作，创建失败时展示具体字段和原因。
10. 帮助中心采用 `B` 方案：主题卡片作为入口，点击主题进入完整步骤正文，配真实截图、重点标注和连续阅读目录。
11. 关闭窗口默认询问；弹窗以“最小化”为主操作，“直接退出”为次操作，并允许记住选择。
12. 页面切换、保存、完成待办、弹窗和设置选择具备克制而明确的动效与反馈，并尊重 `prefers-reduced-motion`。

## 3. 非目标

- 不新增云同步、账号、协作、在线模板市场或远程帮助服务。
- 不更换日志内容权威模型；Tiptap JSON 仍是日志的唯一权威内容。
- 不在本轮重新实现日志 schema、附件存储、Markdown 投影或版本历史基础设施。
- 不新增运行时下载字体、截图、图标或帮助内容；安装包必须离线可用。
- 不保留旧版“关闭到托盘”布尔设置作为第二套并行配置。
- 不为历史测试数据设计复杂迁移；无法确定的旧值迁移到安全的“每次询问”。

## 4. 设计方向

### 4.1 视觉语言

DailyFlow 保持工作型产品而不是展示型站点。界面使用中性纸张感和绿色操作强调色，危险、成功、警告继续使用独立语义色。主题切换只改变界面 token，不改变内容语义和热力图等级。

密度分为紧凑、舒适和宽松三档。密度同时作用于控件高度、列表行高、表单间距和工具栏，不允许只有局部变化。

### 4.2 动效

- 页面和主要面板进入使用 120-180ms 的透明度与短距离位移组合。
- 保存状态、待办完成和知识保存成功使用短暂状态动画，不使用持续闪烁。
- 对话框关闭、开关切换和分段控件使用明确的中间状态。
- 所有非必要动画在 `prefers-reduced-motion: reduce` 下禁用。

### 4.3 可访问性

- 图标按钮必须有不含歧义的可访问名称和悬浮提示。
- 所有交互控件有可见焦点态，键盘可完成模板选择、插入菜单、年份选择、待办切换和关闭确认。
- 正文、表单错误、热点图和帮助截图说明不得仅依赖颜色传达信息。
- 对话框打开后焦点进入标题或第一个字段，关闭后返回触发控件。

## 5. 全局语言与文案架构

### 5.1 根级语言上下文

新增类型化本地化能力，由应用根节点提供：

```ts
type AppLocale = "zh-CN" | "en-US";

interface AppI18n {
  readonly locale: AppLocale;
  readonly t: (key: AppMessageKey, values?: Record<string, string | number>) => string;
  readonly formatDate: (value: Date | string, options?: Intl.DateTimeFormatOptions) => string;
}
```

- `locale` 来自用户偏好，不通过页面局部状态维护。
- 设置切换语言时更新偏好和根上下文，所有订阅页面在同一次 React 更新中重新渲染。
- 日期、数字、相对时间和月份名称统一通过 `Intl` 生成，不拼接中英文自然语言。
- 原生托盘、窗口标题和桌面菜单读取同一语言值；需要 Rust 更新的文案通过类型化命令同步。

### 5.2 消息目录

- 新建按领域拆分的消息目录，例如 `common`、`settings`、`journal`、`tasks`、`timeline`、`knowledge`、`analytics`、`help`。
- 中间层逐步替换现有 `text("中文", "English")` 调用；本次改动涉及的页面必须迁移完成。
- 页面不得直接包含用户可见中文或英文字符串。动态内容通过参数插值，不通过字符串替换。
- 缺少消息键时中文和英文开发测试同时失败；生产回退显示消息键，便于发现问题。
- 模板名称、描述、帮助标题、截图说明和空状态属于消息目录，不留在组件常量中。

### 5.3 验收覆盖

至少覆盖工作台、每日日志、时间线、待办、知识库、搜索、分析、设置和帮助中心。测试在运行时从中文切到英文后逐页验证标题、导航、主要按钮和日期格式已更新。

## 6. 设置页

### 6.1 常规页

- 删除显示设置中无内容的装饰性双横线；每个分隔线必须对应实际分组标题和说明。
- 语言使用两个直接可见的选项：`简体中文`、`English`。
- 关闭窗口行为使用三选一分段控件：`每次询问`、`始终最小化`、`直接退出`。
- 新安装默认 `每次询问`。
- 迁移旧偏好时无法确定用户意图的值统一迁移为 `每次询问`；删除旧 `closeToTray` 写路径。

### 6.2 外观页

- 主题使用三个带界面预览的卡片：浅色、深色、跟随系统。
- 强调色使用可见圆形色块和文字标签；选中态有勾选图标与边框，不只改变颜色。
- 密度使用三个分段按钮，并在旁边显示行高变化预览。
- 所有选项在桌面宽度下直接罗列；窄窗口下自然换行，不出现内部滚动条。
- 不使用原生 `<select>` 承载主题、强调色或密度。

### 6.3 即时生效

设置值写入成功后立即更新根元素数据属性和本地化上下文。写入失败时回滚控件状态并显示字段级错误，不得出现控件显示已保存但实际偏好未更新的状态。

## 7. 窗口关闭行为

### 7.1 配置模型

```ts
type CloseBehavior = "ask" | "minimize" | "quit";
```

- `ask`：拦截关闭请求，显示确认弹窗。
- `minimize`：拦截关闭请求，隐藏主窗口，保持应用运行。
- `quit`：允许应用执行完整退出流程，先 flush 未保存数据。
- Tauri 生命周期状态使用同一三态值，不使用两个布尔值表达。

### 7.2 关闭请求流程

1. 用户点击窗口关闭按钮。
2. Rust 读取当前 `CloseBehavior`。
3. `minimize` 直接隐藏窗口；`quit` 进入显式退出流程。
4. `ask` 阻止默认关闭并向当前窗口发送一次 `close-requested` 事件。
5. 前端显示应用内确认框，焦点落在“最小化”。
6. 用户选择操作；勾选“记住我的选择”时同时更新 `CloseBehavior`。
7. 最小化调用隐藏窗口；退出先等待日志保存协调器 flush，再使用显式退出标志终止进程，避免再次触发询问。

同一时间最多存在一个关闭确认框。若前端未就绪或事件无法送达，默认执行最小化，避免丢失未保存内容。

## 8. 日志编辑器

### 8.1 技术边界

继续使用现有 Tiptap 文档内核，因为 Markdown 快捷输入、附件、结构化块、表格、公式、Mermaid、历史版本和投影能力已经建立。问题在编辑器产品层，不需要更换内容内核。

本次重做 `JournalEditor` 的页面结构、模板入口、插入操作和工具栏组织。序列化、保存协调器和 schema 继续作为稳定的下层能力。

### 8.2 初始模板选择

新建且正文为空的日志先显示模板页：

- 顶部显示日志日期和简短说明。
- 第一区展示最近使用，按最近使用顺序最多四个。
- 第二区展示空白日志、内置模板和自定义模板卡片。
- 内置模板至少包含日报、周报、问题排查和复盘。
- 自定义模板包含名称、说明、初始 Markdown，并显示预览。
- 选择模板后立即进入正文，当前模板记录为最近使用。

已存在内容的日志不强制显示模板页，可通过正文工具栏“模板”按钮重新打开选择器。

### 8.3 正文布局

- 顶部文档栏：标题、日期、保存状态、模板、历史、沉淀和更多操作。
- 中部左侧为正文，右侧为可折叠大纲；窄窗口下大纲变为可打开抽屉。
- 页面本身不滚动，正文区域独立滚动。
- 低频操作收进“更多”菜单，避免顶部按钮在 1024px 宽度换行遮挡。
- 标签编辑放在正文下方固定区域，不挤压工具栏。

### 8.4 当前行插入入口

移除六点拖拽手柄。鼠标位于正文块或键盘光标进入块时，在该块左侧显示 `+`：

- 点击打开插入菜单。
- 插入菜单包含标题、项目列表、编号列表、任务列表、引用、代码块、表格、图片、附件、公式、Mermaid。
- 选择图片或附件后打开文件选择器并把结果插入当前块之后。
- `+` 只能有一个可见实例；焦点离开时消失，菜单打开时保持可见。
- 六点拖拽不作为可见操作保留；块排序可通过插入菜单中的“移动块”子项完成，或留到独立后续能力。

### 8.5 Markdown 快捷输入

- 输入 `#` 到 `######` 后的半角或全角空格时转换对应标题。
- `## 你好` 和 `##　你好` 均生成二级标题。
- 标题更新后大纲立即刷新。
- 代码块、行内代码、表格单元格和已有标题内不触发。
- 快捷输入行为由编辑器扩展测试覆盖，不使用 DOM 后处理。

### 8.6 模板持久化

- 自定义模板和最近模板 ID 继续使用本地模板库存储。
- 加载非法或过期模板 ID 时忽略，不清空其他自定义模板。
- 最近模板最多保存八个，界面显示前四个。

## 9. 时间线与热力图

### 9.1 可编辑年份选择器

月历、时间线和热力图共用一个年份选择组件：

- 触发按钮显示当前年份。
- 打开后显示可编辑四位年份输入，允许 `1..9999`。
- 输入合法年份后确认并刷新。
- 提供“今年”“去年”“前年”快捷按钮。
- 展示十二个月网格，点击月份直接跳转。
- 使用日期组件约束，不生成固定年份列表。
- Esc 关闭，Enter 确认，方向键在月份网格移动。

### 9.2 绿色活动色阶

- 使用五档绿色 token：无活动、低、较低、中、高、最高。
- 色值在浅色和深色主题下分别定义，并满足文本和边界可辨识性。
- 今天、选中日期和键盘焦点使用边框区分，不改变活动等级颜色。
- 任务到期使用角标或小三角，不把整格改成非绿色。

## 10. 知识库与待办可靠性

### 10.1 知识库弹窗

新建知识和整篇日志沉淀使用大尺寸沉浸弹窗：

- 桌面宽度约为视口 92%，最大宽度 1180px；高度约为视口 86%，最大高度 860px。
- 弹窗本身不滚动，标题栏与底部操作栏固定。
- 正文编辑区独立滚动。
- 右侧栏包含知识类型、摘要和文档信息；窄窗口下移到底部。

### 10.2 知识保存错误链路

- Rust repository 保存知识时，`summary`、`content_plain_text` 和 `content_markdown` 使用各自真实来源，不再把摘要写入纯文本后把 Markdown 留空。
- IPC 错误保留 `AppError.code`、字段错误和用户可读 cause。
- 新建与沉淀弹窗按 `VALIDATION_ERROR`、`CONFLICT`、`NOT_FOUND`、`STORAGE_UNAVAILABLE` 显示不同恢复建议。
- 未知错误记录开发日志并显示“保存失败”及可获取的具体原因，不统一覆盖成“请重试”。
- 保存按钮在请求期间禁用并显示进度；成功后再关闭弹窗并导航或显示成功反馈。
- SQLite 集成测试使用临时数据库覆盖新建、整篇日志沉淀和中文内容 roundtrip。

### 10.3 待办创建与状态

- 标题与日期在提交前显示字段级校验，日期使用日期输入并统一序列化为 `YYYY-MM-DD`。
- 后端字段错误映射回对应输入，不把全部失败显示成同一句提示。
- 每行始终显示明确的“完成”或“重新打开”文字按钮，并单独保留“编辑”。
- 圆圈仍可快速切换；从待办完成后提供短暂视觉反馈，但不能延迟数据刷新。
- 已完成列表仍可直接重新打开，错误时恢复旧状态并显示内联提示。

## 11. 帮助中心 B

### 11.1 信息架构

帮助中心采用 `B` 主题卡片入口：

- 首屏是紧凑的帮助首页，不是营销页。
- 顶部提供搜索、语言状态和“查看完整手册”入口。
- 主题卡片按“快速开始、日志、待办、时间线、知识库、数据与设置”分组。
- 每张卡片包含图标、主题、摘要、步骤数和最近更新时间。
- 点击卡片进入该主题正文，并在同一内容源中定位对应章节。

### 11.2 内容呈现

- 唯一内容源是一份带稳定章节 ID 的中英文手册。
- 主题正文包含左侧目录、连续正文和右侧截图说明；窄窗口只保留顶部目录。
- 每一步使用编号、动作说明、预期结果和故障恢复路径。
- 截图来自实际 DailyFlow 页面，包含标注框和简短说明，不使用装饰性示意图。
- 支持全手册关键字搜索，结果显示主题和章节，不只显示文章标题。
- 搜索无结果时给出建议关键词，不显示空白区域。

### 11.3 首版主题

首版至少覆盖：

1. 创建并编辑每日日志。
2. 选择模板、保存自定义模板和沉淀日志。
3. 创建、完成和重新打开待办。
4. 使用时间线、年份选择和热力图。
5. 新建知识项与恢复来源。
6. 切换语言、主题和密度。
7. 设置关闭行为与备份数据。

### 11.4 资源

- 截图以本地 WebP 或 PNG 资源随应用打包。
- 帮助正文不得依赖远程图片 URL。
- 截图有本地化 alt 文本和说明文字。
- 内容或截图路径缺失时构建测试失败。

## 12. 错误与状态约定

- UI 不显示 `unknown`、JS 异常堆栈或数据库原文。
- `AppError` 的用户消息优先来自稳定错误码映射，字段错误优先显示具体字段。
- 取消操作不显示红色错误。
- 加载、保存中、成功、可重试失败和冲突具有不同组件状态。
- 业务表单失败时保留用户输入；成功前不清空。
- 所有错误提示必须可被屏幕阅读器读出，并在操作焦点附近出现。

## 13. 模块边界

- `@dailyflow/shared`：稳定错误码与通用结果类型。
- `@dailyflow/application`：偏好、知识、待办和日志用例；不依赖 React 或 Tauri。
- `@dailyflow/editor`：Tiptap schema、快捷输入、文档投影和大纲。
- `@dailyflow/ui`：对话框、分段控件、主题预览、卡片、色块和动效 token。
- `@dailyflow/features`：各页面和产品交互组合。
- `@dailyflow/desktop`：根级 i18n、路由和桌面服务装配。
- `apps/desktop/src-tauri`：三态关闭行为、SQLite repository 和 IPC 命令。

禁止浏览器组件直接调用 Tauri API；通过 application port 和 composition root 注入。

## 14. 测试策略

### 14.1 受保护行为的失败测试

按 TDD 顺序先写以下失败测试：

- 切换语言后每个主要路由标题和主要操作更新。

## 16. 风险与缓解

- **全量文案迁移范围过大：** 先建立类型化目录和根上下文，再以本次受影响页面为必须完成集，测试阻止残留硬编码。
- **关闭事件重复触发：** 使用单一 Rust 原子状态和显式退出标志，前端同一时间只允许一个关闭弹窗。
- **保存期间直接退出：** 显式退出先调用日志 flush，失败时允许用户取消退出。
- **知识保存错误根因隐藏：** 先用 SQLite 集成测试复现并保留字段级错误，再修 UI，不只改文案。
- **Tiptap 产品层改动影响 schema：** 不修改文档结构；快捷输入、插入和模板行为通过现有序列化边界测试保护。
- **帮助截图失效：** 截图路径纳入构建和测试；使用稳定文件名并在内容模块集中引用。
- **年份值溢出：** 日期组件与选择器共同限制 `1..9999`，所有转换使用整数校验。
- **动效影响可访问性：** 统一使用短时 CSS transition，并提供 reduced-motion 覆盖。
