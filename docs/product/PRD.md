| 项目 | 内容 |
| --- | --- |

## 2. 产品定位

DailyFlow 是个人工作记忆系统。用户每天以低摩擦方式记录工作过程，随后通过时间线、搜索和知识库把零散记录转化为可复用的经验。

产品的核心价值不是“拥有一个富文本编辑器”，而是形成以下闭环：

```text
快速记录 -> 自动保存 -> 日/周/月回看 -> 检索问题 -> 提炼知识 -> 再次使用
```

### 2.1 目标问题

1. 按月目录、按天 TXT 的方式容易记录，但跨文件检索、回看和问题复用困难。
2. 普通笔记工具缺少“工作日志、问题、解决过程、待办”之间轻量的关联。
3. 结构化知识库录入成本高，强制模板会破坏每日记录的自然流。
4. 纯云笔记工具让用户担心隐私、断网和长期数据可迁移性。
5. 现有工具难以无损迁移历史 UTF-8/GBK TXT 日志。

### 2.2 产品原则

- **记录优先**：打开当天日志即可写，不要求先选模板或分类。
- **本地可信**：数据在用户设备上可用，导出格式可理解、可恢复。
- **单源一致**：日志正文只有一个权威表示，搜索和导出由它派生。
- **渐进结构化**：先自由记录，需要时再把片段升级为问题、方案或知识条目。
- **能力可替换**：存储、附件、搜索和 AI 都通过接口隔离。
- **不做过度自动化**：AI、摘要和标签建议默认关闭，不能阻塞关键流程。
- **兼容非目标平台**：V1 不发布 Linux 版本，但不把 Windows 路径或系统细节写入领域模型。

## 3. 目标用户与使用场景

### 3.1 核心用户

个人开发者、测试工程师、运维人员、技术负责人，以及有持续工作记录习惯的知识工作者。用户通常每天产生多条短记录，偶尔包含长代码块、排错日志、截图和附件。

### 3.2 关键使用场景

1. 早晨打开 DailyFlow，查看今日待办和昨日未完成事项。
2. 在工作中随时记录问题、尝试、结论和代码片段。
3. 下午回到某天的日志，补录上午未记录的内容。
4. 用关键词搜索过去半年中的报错信息和解决方案。
5. 将一次排查过程提炼为“问题 + 原因 + 解决方案”知识条目。
6. 周末查看本周日志、完成任务和问题解决数量，生成可编辑周报草稿。
7. 把旧电脑中的月份目录导入新设备，并在导入前检查重复和编码异常。
8. 导出 Markdown 或完整备份，换设备或防止误删。

### 3.3 非目标用户

- V1 不面向团队协作、审批流或企业知识库。
- V1 不提供实时多人协同。
- V1 不承担云盘、文件同步或账号系统职责。
- V1 不面向需要公开发布博客或网站的用户。

## 4. 产品目标与非目标

### 4.1 V1 产品目标

| 目标 | 可验收结果 |
| --- | --- |
| 快速记录 | 新建当天日志到可输入不超过 2 个主要操作 |
| 数据安全 | 自动保存、版本历史、完整备份与恢复可用 |
| 历史迁移 | 可批量扫描月份目录并导入带 BOM/GBK 的 TXT |
| 历史检索 | 可按关键词、日期、类型定位日志和知识条目 |
| 经验沉淀 | 可从日志生成知识条目，也可独立创建 |
| 回看与总结 | 日历、时间线、热力图、周/月/年统计清晰可用 |
| 跨端一致 | 同一功能名词、数据模型和核心交互在桌面与 Web 一致 |
| 可扩展 | 存储、搜索、附件、同步和 AI 均通过边界接口隔离 |

### 4.2 V1 非目标

- 账号注册、登录、订阅、支付和云端服务。
- 多设备自动同步、冲突合并 UI、共享空间和评论。
- 移动原生 App。
- 插件市场、主题市场、脚本插件系统。
- 双向 Markdown 与富文本独立编辑。
- 强制日报模板、审批流、工时计费、OKR 或项目管理套件。
- Office 文档在线预览、PDF 批注和复杂媒体编辑。
- Linux 正式安装包、签名和发布验收。
- AI 自动改写全部日志、自动执行工具调用或依赖 AI 才能使用的功能。

## 5. 信息架构

V1 顶层导航固定为：

1. **Dashboard**：今日状态、继续记录、待办、近期知识和数据概览。
2. **Daily Journal**：按日期创建和维护每日日志。
3. **Timeline**：日历、时间线、热力图和历史回看。
4. **Knowledge Base**：笔记、问题、解决方案和关系浏览。
5. **Tasks**：轻量个人待办。
6. **Search**：跨实体全文搜索和筛选。
7. **Analytics**：周报、月报、年度总结和统计。
8. **Data Management**：导入、导出、备份、恢复和存储信息。

设置作为独立入口，不占主导航一级模块。

## 6. 核心实体

| 实体 | 用户含义 | 关键关系 |
| --- | --- | --- |
| Journal | 某一天的工作日志 | 可有多个历史版本、标签、附件、关联任务 |
| Journal Version | 日志在某个时间点的历史快照 | 属于一个 Journal |
| Structured Block | 日志中的结构化片段，如问题、决策、方案 | 属于一个 Journal，可被提升为 Knowledge Item |
| Task | 轻量个人待办 | 可关联一个 Journal 或 Knowledge Item |
| Knowledge Item | 可复用的笔记、问题、方案或决策 | 可引用来源 Journal/Block，可关联标签和附件 |
| Tag | 跨实体分类 | 与 Journal、Knowledge Item 多对多 |
| Attachment | 图片或文件 | 属于 Journal 或 Knowledge Item |
| Import Session | 一次 TXT 批量导入及其结果 | 包含多个 Import Entry |
| Report | 周/月/年总结草稿或统计快照 | 可关联日期范围 |

## 7. 功能需求

### 7.1 Dashboard

**目标**：在一屏内回答“今天该做什么”和“最近留下了什么”。

**功能**

- 显示今天日期、时区和当前日志保存状态。
- 提供“继续记录今天”主操作；当天无日志时可一键创建。
- 显示今天和逾期的未完成待办，可快速勾选完成。
- 显示最近编辑的 3 至 5 篇日志。
- 显示最近 3 至 5 个知识条目。
- 显示最近 12 周记录热力图和本周简短统计。
- 当数据库为空时显示导入历史 TXT、创建第一篇日志两个入口。

**验收标准**

- Dashboard 所有区域均可跳转到对应详情。
- 今日日志加载和保存状态明确，不用颜色作为唯一状态信号。
- 大屏为多栏工作台，窄屏改为单列，不出现层级卡片嵌套。
- 空状态不伪造统计数据。

### 7.2 Daily Journal

**目标**：提供足够快、可离线、不会强制模板的日常记录体验。

**功能**

- 以本地日历日期 `YYYY-MM-DD` 标识每日日志，每天最多一篇主日志。
- 打开当天日期时生成未保存的编辑器草稿，首次成功保存后才创建数据库记录；也可选择历史日期补录。
- 编辑器支持标题、粗体/斜体、列表、引用、代码块、链接、图片和附件。
- 支持 Tiptap 的行内格式和 ProseMirror 快捷键。
- 支持 Markdown 快捷输入和 Markdown 粘贴解析。
- 支持可选结构化内容块，至少包含：`issue`、`solution`、`decision`、`note`、`todo`。
- 自动保存，显示“未保存 / 保存中 / 已保存 / 保存失败”，失败可重试。
- 关闭窗口或切换页面前尽力完成保存；可恢复未成功写入的编辑内容。
- 支持历史版本查看和恢复，恢复也生成新版本。
- 日志可添加标签、引用任务、转为知识条目。
- 不提供必须填写的固定模板。

**验收标准**

- 输入停止约 800 毫秒后触发保存，连续输入不会重复创建日志。
- 刷新或重启后最近成功保存的内容不丢失。
- 保存失败时正文保留在编辑器中，不清空、不覆盖服务器或本地旧版本。
- 同一日期并发保存通过 revision 检查拒绝静默覆盖。
- 导入的纯文本原始内容可通过来源记录追溯。

### 7.3 Timeline

**目标**：从时间维度理解记录密度、连续性和历史上下文。

**功能**

- 月历视图，标记有日志、有待办截止日、有重要知识条目的日期。
- 时间线视图，按日期倒序展示摘要、标签和关键统计。
- 12 周日历热力图，色阶表示当天正文字符数或记录条数；统计口径在 UI 中说明。
- 点击日期进入日志；未来日期允许补录计划但不得伪装为已完成记录。
- 支持年月跳转和快速回到今天。

**验收标准**

- 日期使用用户本地日历，不使用 UTC 日期直接切天。
- 日历月份边界、闰年、年末切换正确。
- 热力图在无数据时显示为空状态。
- 时间线查询有分页或游标，不一次性加载全部历史正文。

### 7.4 Knowledge Base

**目标**：把可复用的经验和问题从日志中沉淀出来。

**功能**

- 列表、筛选和详情视图。
- 类型：`note`、`issue`、`solution`、`decision`、`reference`。
- 可独立创建，也可从日志正文或结构化块“提升”为知识条目。
- 问题类型支持“现象、原因、解决过程、最终方案、预防措施”等可选字段。
- 支持标签、来源链接、相关条目关联和附件。
- 支持列表按更新时间、创建时间、标题、类型过滤。
- 删除默认进入回收站状态，可在数据管理中清理；V1 可先只提供软删除和恢复。

**验收标准**

- 从日志提升时保留来源日志 ID、块 ID 和创建时快照关联。
- 修改知识条目不回写原日志；用户可显式插入反向链接。
- 问题与方案可建立有方向的关联。
- 正文编辑与日志使用同一编辑器能力和权威数据规则。

### 7.5 Tasks

**目标**：提供不打断日志记录的轻量待办。

**功能**

- 创建、编辑、完成、重新打开、取消和删除任务。
- 字段：标题、备注、状态、优先级、截止日期、可选关联实体。
- 视图：今天、即将到期、全部、已完成。
- 可从当前日志创建任务，也可将任务插入日志引用。
- Dashboard 可快速完成今天或逾期任务。

**非目标**：重复任务引擎、甘特图、子任务无限层级、多人指派、工时统计和提醒通知中心。

**验收标准**

- 完成任务记录 `completed_at`，再次打开时清空该字段。
- 截止日期是本地日历日期，不因时区变化漂移。
- 删除待办不删除关联日志或知识条目。

### 7.6 Search

**目标**：快速找到历史工作内容，而不是只搜索标题。

**功能**

- 全局搜索日志标题、正文、结构化块、知识条目，以及任务的标题、备注、状态和截止日期；日志和知识条目的标签也进入搜索范围。
- 支持按实体类型、日期范围和标签过滤；标签过滤只作用于带标签的日志和知识条目。
- 结果展示命中片段、实体类型、日期和最后更新时间。
- 支持键盘打开搜索、上下选择、回车进入详情。
- 支持中文、英文、数字和代码标识符的基础检索；大小写和全半角归一化。
- 首版不要求复杂布尔表达式、正则和向量检索。

**验收标准**

- 常规保存把正文、派生投影和搜索索引作为一次原子提交；任一步失败时整次保存回滚，编辑器保留草稿，不产生正文成功但索引半写入的状态。
- 删除或软删除实体后不出现在默认搜索结果。
- 搜索结果不得读取或返回附件二进制内容。

### 7.7 Analytics

**目标**：帮助回看工作节奏并生成可编辑的总结草稿。

**功能**

- 周、月、年三个统计周期。
- 统计：日志天数、记录字数、任务完成数、问题新增/解决数、知识条目数、活跃标签。
- 周报/月报/年度总结：系统生成确定性的结构化草稿，用户可编辑并保存为 Report。
- 后续启用可选 Provider 时可调用 AI 优化摘要；V1 未配置 Provider 时所有统计和基础草稿仍完整可用。
- 显示统计口径和缺失数据提示。

**非目标**：绩效评分、团队排名、预测性分析、自动评价个人产出。

**验收标准**

- 相同数据和周期在无 AI 时生成稳定结果。
- 统计结果注明时区和日期范围。
- 报告中引用日志时可跳转原文。

### 7.8 Data Management

**目标**：让用户清楚数据在哪里、如何迁移、如何恢复。

**功能**

- TXT 历史日志导入向导：扫描、识别、预览、选择冲突策略、执行、查看结果。
- 增量导入：已导入且哈希相同的文件默认跳过。
- Markdown/JSON 数据导出。
- 完整备份和恢复，包含正文、版本、标签、任务、知识条目、导入来源和附件。
- 显示存储类型、数据库版本、占用空间、最后备份时间和附件数量。
- 提供全文索引重建和一致性检查。
- 危险操作需要二次确认并明确影响。

**验收标准**

- 导入失败时事务回到执行前状态。
- 原始 TXT 内容以字节形式保留，可回溯编码和哈希。
- 备份包含 manifest、schema 版本和应用版本。
- 恢复前校验格式、版本和附件完整性；恢复失败不得破坏当前数据。

## 8. 编辑器产品需求

### 8.1 支持能力

- Markdown 输入与粘贴。
- 标题、段落、有序/无序列表、任务列表、引用、分隔线。
- 行内代码、代码块、链接、粗体、斜体、删除线。
- 图片、附件和外部链接。
- 可选结构化块。
- 撤销/重做、查找、字数统计。
- 自动保存、版本检查、恢复和快捷键。

### 8.2 权威数据规则

- Tiptap JSON 是 Journal 和 Knowledge Item 正文的唯一权威来源。
- Markdown、纯文本、结构化投影和搜索文本为派生数据。
- 派生数据只能由保存用例重新生成，不能被单独编辑。
- 外部 Markdown 导入必须通过解析器生成 Tiptap JSON。
- 历史 TXT 导入同时保留原始字节和转换后的编辑器正文。
- 不提供“同一个文档可同时独立编辑 JSON 与 Markdown”的界面。

### 8.3 自动保存体验

- 停止输入约 800 毫秒后保存。
- 状态栏显示保存状态和最后成功时间。
- 保存失败保留当前编辑缓冲区，并提供重试和查看错误。
- 保存成功后才更新“已保存”并允许关闭确认通过。
- 恢复历史版本不会删除当前版本，而是生成新的恢复版本。

## 9. 历史 TXT 迁移需求

### 9.1 输入形态

典型目录：

```text
logs/
├─ 202504/
│  ├─ 2025-04-01.txt
│  ├─ 20250402.txt
│  └─ 04-03.txt
├─ 202505/
└─ ...
```

### 9.2 识别规则

- 月份目录：`YYYYMM`。
- 文件名日期：优先识别 `YYYYMMDD`、`YYYY-MM-DD`、`YYYY.MM.DD`、`YYYY_MM_DD`。
- 月份目录内的 `MMDD`、`MM-DD`、`MM.DD` 与目录年份组合。
- 无法确定日期时不允许静默使用修改时间；标记为异常并要求用户指定日期或跳过。
- 编码识别顺序：UTF-8 BOM、严格 UTF-8、GB18030（兼容 GBK）。
- 空文件、超大文件、非 TXT 文件、损坏路径、重复日期和重复哈希分别提示。

### 9.3 导入结果

导入完成后显示：

- 扫描文件数、可导入数、跳过数、冲突数、异常数。
- 成功创建的日志数、更新的日志数、导入的原始字节数。
- 按编码和异常原因分类的统计。
- 批次 ID、执行时间、失败项和恢复入口。

### 9.4 安全要求

- 预览阶段不写入正式日志。
- 用户确认后使用单事务或等价原子机制提交。
- 任一文件失败时整批回滚，并保留可读错误报告。
- 默认不覆盖已有日志正文；冲突必须由用户选择跳过、追加或作为新版本导入。
- 原始 TXT 字节与解码文本分开保存，禁止只保留转换后的富文本。

## 10. 跨平台需求

### 10.1 支持基线

| 平台 | V1 基线 | 说明 |
| --- | --- | --- |
| Windows | Windows 10 22H2 及以上、Windows 11 | 使用 WebView2 Evergreen，安装包提供引导检查 |
| macOS | macOS 12 及以上，Intel 与 Apple Silicon | V1 分别发布 Intel 与 Apple Silicon 包；两者都需 Developer ID 签名与公证 |
| Web | 最新两个稳定版 Chrome/Edge；Safari 当前稳定版尽力支持 | 目录批量选择能力允许降级 |

Linux 不进入 V1 发布矩阵，但领域、路径、快捷键和测试中不得假设 Windows。

### 10.2 平台差异

- 数据目录由 Tauri 的应用数据目录 API 解析，不硬编码盘符或用户目录。
- macOS 使用 `Cmd`，Windows/Web 使用 `Ctrl`，统一通过 `Mod` 抽象。
- 文件路径只在基础设施层处理；数据库存储逻辑路径或相对路径。
- 桌面端通过原生文件对话框和 Rust 文件服务读写附件。
- Web 端通过 File System Access API、文件输入或下载回退完成导入导出。
- Web 存储受浏览器配额和清理策略影响，必须显示持久化状态与备份提醒。
- 桌面端关闭窗口需要等待保存；Web 端使用 `visibilitychange`/`pagehide` 尽力保存。

## 11. 非功能需求

### 11.1 性能

- 10 万篇日志元数据、100 万条任务/知识记录规模下，Dashboard 首屏目标小于 2 秒，不含首次索引重建。
- 常规日志打开 P95 小于 500 毫秒（本地 SSD、已建立索引）。
- 1 万字符日志停止输入后 1.5 秒内完成本地保存和索引更新。
- 搜索结果首屏 P95 小于 300 毫秒（本地常见数据集）。
- 列表必须使用分页/游标，不能一次渲染所有正文。

### 11.2 可靠性

- 保存、导入、恢复、附件关联必须原子或可恢复。
- 数据库迁移在事务中执行，失败时保留旧版本。
- 备份恢复前先创建安全快照或使用临时数据库验证。
- 任何索引或派生数据损坏都应可从权威正文重建。

### 11.3 安全与隐私

- V1 无默认网络请求和账号上传。
- AI 默认关闭，启用时明确显示将发送哪些内容、发送目标和费用风险。
- API Key 桌面端优先系统钥匙串；Web 端不得在 IndexedDB 明文长期保存第三方密钥。
- 外部链接使用安全协议，附件名称进行路径净化。
- 导出和备份目录由用户选择，不在日志中暴露绝对路径。

### 11.4 可访问性

- 键盘可完成主要工作流。
- 颜色不是唯一信息载体。
- 焦点状态、对比度和语义化标签满足 WCAG 2.1 AA 的可实现部分。
- 编辑器工具栏按钮提供可访问名称和快捷键提示。

### 11.5 国际化

- V1 界面默认简体中文，代码和数据结构采用英文。
- 日期、数字、星期使用统一格式化层，不散落字符串拼接。
- 文件编码与本地日期是数据语义的一部分，不随界面语言变化。

## 12. 数据与隐私策略

- 默认所有数据保存在本地。
- 不采集遥测；如未来增加，必须显式 opt-in。
- 崩溃日志默认本地保存，用户主动导出，不自动上传。
- 删除数据前说明是否包含附件、历史版本和导入原始文件。
- 备份文件默认不加密，但 UI 必须提示其包含敏感内容；后续可增加加密备份。
- AI 请求应最小化上下文，不默认发送附件、代码块或整篇历史。

## 13. 成功指标

V1 以个人可用性和数据可信为主要指标，不引入助长焦虑的每日连续打卡惩罚。

| 指标 | 目标 |
| --- | --- |
| 首篇日志创建耗时 | 新用户 60 秒内完成首个有效记录 |
| 自动保存成功率 | 测试与试用期间大于 99.9%，无静默数据丢失 |
| 导入成功率 | 支持编码的合法 TXT 文件成功率大于 99% |
| 搜索返回率 | 真实历史样例中可定位目标日志的查询大于 90% |
| 备份恢复校验 | 跨端恢复后核心实体计数、正文哈希和附件哈希一致 |
| 崩溃恢复 | 强制终止后最多丢失最近约 1 秒内的编辑 |

## 15. 产品风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| Tiptap JSON 与 Markdown 双写不一致 | 数据损坏 | JSON 单一权威，序列化测试，派生字段不可独立写 |
| GBK 文件误判 | 内容乱码 | BOM/严格 UTF-8 后回退 GB18030，预览可切换编码 |
| 浏览器清空 IndexedDB | 数据丢失 | 持久化请求、备份提醒、导出入口和使用说明 |
| 大量 TXT 一次性导入内存过大 | 崩溃 | 扫描流式处理、批次限制、预览摘要和分块解析 |
| 自动保存版本爆炸 | 数据库膨胀 | 正文当前状态与历史检查点策略分离 |
| Web/桌面能力差异 | 行为不一致 | 端口抽象、能力检测、共享契约测试 |
| 未来同步推翻数据模型 | 迁移成本高 | 稳定 UUID、逻辑日期、revision、软删除、同步契约先行 |
| AI 引入隐私风险 | 信任受损 | 默认关闭、显式确认、最小上下文和可插拔 Provider |

## 16. 待确认产品决策

以下事项不阻塞架构设计，但应在开发前确认：

1. **历史版本保留策略**：建议 V1 保留最近 100 个检查点和 180 天版本，用户可手动导出完整历史。
2. **软删除保留期**：建议日志和知识条目进入回收站保留 30 天，任务直接软删除并可恢复。
3. **Web 浏览器基线**：建议正式验收 Chrome/Edge，Safari 作为兼容范围；若必须完整支持 Safari 目录导入，需接受文件选择器降级。
4. **macOS 分发方式**：V1 分别发布 Intel 与 Apple Silicon DMG，两种架构都需实际安装启动验收，并完成 Developer ID 签名与公证；Universal 2 仅作为后续可选产物，不能替代双架构验证。
5. **历史版本是否在 V1 提供全文 diff**：建议 V1 只提供纯文本/渲染视图对比，不做复杂逐词 diff。
